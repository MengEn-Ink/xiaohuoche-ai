# 小火车日报 HTML

把零散骑行素材整理成可浏览、可直接导出公众号图片的单页 HTML。核心目标是：**原话优先、少写少错、图片不重复、像群内手工刊物而非企业模板**。

## 输入确认

开始制作前整理：

1. 用户给出的事实条目或初稿。
2. 用户提供的图片及其大致主题。
3. 日期、标题、是否部署，以及是否需要整页/分屏 PNG。所有部署后的日报 HTML 链接默认带常驻批注能力，不需要重复询问。

信息足够时直接执行。地点、人物称呼、活动时间或专有梗不明确时保留原话，不自行解释。

## 文案压缩

- 一条素材对应一个章节，不把同一事实拆成多个剧情。
- 保留原句的主语、动作、对象、时间和笑点，只做标点、断句和轻量顺序整理。
- 用户要求“按照我的话术”时，正文尽量直接使用原句；不添加因果、动机、评价或安全提醒。
- 大标题从原话截取最有梗的 4–12 字，正文通常每章 1 句、最多 3 行；同一信息只出现一次，标题已经说清的内容不在正文重复。
- 用户说“第一张/第二张”“上面/下面”“这个图”等只用于说明素材对应关系，默认不进入成稿。
- 不为追求视觉效果在一句话中频繁插入 `<br>`；优先让浏览器按容器自然换行，每行保持完整语义短语，避免几个字单独成行。
- 删除解释句、总结腔和二次发挥；历史感来自梗密度与排版，不来自虚构新梗。
- 保持 `Ride`、`XDM`、🐟、🦐 等群内称呼和表情；对外缩写固定为 `XZQ`。

## 图片唯一编排

先建立“文件 → 章节”映射：

- 每张图片最多出现一次，封面与正文合并计算；人物原图、抠图和描边图按 sidecar `source_sha256` 视为同一源，其他图片按文件字节 SHA256 判同源。改文件名、复制文件或换用同源衍生图都不得绕过门禁；同一期贴纸也不得重复。
- 图片不足时用色块、粗标题和高密度文字卡片承载，不复制图片填空；控制章节上下留白，避免出现大面积只有背景没有信息的空区。
- 新素材足以表达主题时，移除与当期话题弱相关的旧风景照片，不为凑版保留历史配图。
- 图片多时可在同一章节做双图拼版，但每张仍只出现一次；构图必须保留原图中的全部人物，不得因放大遗漏边缘人物。
- 放大前先按人物数量选择策略：单组核心人物可用 `cover + scale` 做近景，但缩放锚点必须对准人物；双人或群像素材必须先保证所有人的头部、脸和身体主体完整，再放大，必要时改用 `contain`，禁止用统一裁切参数硬套。
- 用户要求移除某张图时，要同时删除页面引用与交付目录中的图片文件；可保留对应事实文字，但不能用其他旧图替补。
- 图文融合优先使用图片安全区域、渐变遮罩和紧凑文字块；文字不得压住任何人物的脸、身体主体、服装标识或关键动作。
- 不确定图片内容时写“活动插图”“群聊截图”等中性说明，不捏造地点或人物。
- 网页图片转为 WebP，最长边建议不超过 1600px，质量 82–88；截图/路线图优先完整展示。

## 贴图与表情包自由发挥

- 日报默认允许根据当期内容自由选择、搜索贴图或表情包，无需逐张向用户确认；用户明确指定素材或要求不加装饰时，以用户要求为准。
- 素材优先级为：用户提供素材 → `style/stickers/` 已审核贴纸库 → OpenMoji/Twemoji 开放素材。外部素材先登记到贴纸库，再复制到当期 `assets/`，禁止直接热链。
- 每个章节最多使用 1–2 个贴图或表情包，同一文件整篇只出现一次；贴图只能增强情绪和笑点，不得新增人物、事件、结论或未经确认的事实。
- 贴图优先放在标题或图片边缘的空区，可以轻微倾斜和压边框，但不得遮挡文字、人脸、身体主体、服装标识、截图关键信息或水印安全区。
- 贴图在视觉契约中标记 `data-subject="none"`；若使用绝对定位，必须为正文保留真实安全区域，并在桌面端、移动端和 1080px 导出图中验证无重叠、溢出和空白扩张。
- OpenMoji 通过 Iconify 官方公共 API 搜索，Twemoji 按 Unicode 字符获取固定版本素材；导入清单必须记录来源、作者、许可、许可链接和 SHA256。
- GIPHY/Tenor 禁止自动导入：标准 API 要求品牌露出且禁止自行缓存媒体；SOOGIF 和无明确许可的中文斗图站也禁止自动下载。需要这些素材时只提供候选页面，由用户确认授权并上传原文件。

网络贴图工作流：

```bash
# 建议使用英文关键词搜索 OpenMoji
python3 pipeline.py sticker-search "astonished" --limit 8

# 选择结果后下载并登记到 style/stickers/external/
python3 pipeline.py sticker-import openmoji:astonished-face \
  --provider openmoji --name "震惊脸" --use "震惊/不敢细看"

# 标准 emoji 可直接导入 Twemoji
python3 pipeline.py sticker-import "😲" \
  --provider twemoji --name "震惊 Emoji" --use "震惊/意外"
```

## 发布渠道

- 日报禁止使用飞书文档、飞书妙搭页面或 `bytedance.feishu.cn/page/...` 形式发布和交付。
- 线上日报只使用独立静态 HTML/AIME Site（`*.aime-site.bytedance.net`）链接；无法部署到 AIME Site 时只交付本地 HTML 与 PNG，不用飞书页面替代。

运行 [validate_ribao_html.py](scripts/validate_ribao_html.py)：

```bash
python3 scripts/validate_ribao_html.py <HTML文件路径>
```

非零退出码表示存在旧缩写、资源缺失或重复图片，不能交付。

### 最高优先级视觉红线（不可覆盖、不可降级）

以下规则是项目最高优先级，优先于任何历史范例、新增版式、自动布局、贴纸和审阅功能；后续能力合并只能增强，任何冲突都以本节为准：

- **字多横向成行**：总字数超过 10 字、单句超过 6 字或超过 2 个语义短句时，必须使用横向自然行展示；禁止竖排、窄列、逐字列展示。让浏览器按完整语义自然换行，不用连续 `<br>` 切碎文案。
- **字少才可成列**：仅总字数不超过 10 字、最多 2 个短句且单句不超过 6 字的口号/强调词，可以使用纵向列式展示；“可以”不等于“必须”，可读性不足时仍用横向。
- **大字强对比**：正文展示字不得小于 68px；长句宁可自然换行，也不能缩成普通正文小字。页面以单一天蓝底贯穿，逐行大字使用荧光绿、亮黄、白、粉紫、青、蓝紫，文字必须有粗黑描边或白色硬阴影；禁止整屏换色、低对比、灰淡和轻柔卡片风。
- **高密度但不拥挤**：每屏保持大字、主体图、色块与必要贴纸的紧凑组合，优先压缩外边距、空卡和纯背景面积；不允许用大面积留白换取过检，也不能通过缩小字体制造“高密度”。
- **人物抠图放大且主体绝对安全**：人物优先做非生成式抠图，裁透明空边后等比例放大为画面主体；文字、色块和贴纸不得遮挡人物脸部、身体主体、服装标识和关键动作。群像必须保留全部人物，抠图失败则使用原图安全裁切，不生成补全。
- **真实避让**：安全避让必须由真实排版与 `subject-safe` 契约共同保证，不得用虚假主体区、假标记或统一禁止叠层绕过门禁。

### 强制视觉契约

“文字不挡人、内容不留白”不能只靠肉眼记忆；正文和封面必须写入以下机器可检查标记，并通过 `pipeline.py ribao-check`：

- 每个 `<section>` 与封面 `.cover` 标记 `data-density="compact"`，表示该内容区已经压缩外边距、空卡和无信息背景；缺一项即阻断。
- 每张图片必须标记 `data-subject="people"` 或 `data-subject="none"`，不得用漏标绕过人物检查。
- 人物图必须位于 `data-layout="subject-safe"` 容器内，并用 `data-subject-zone="x,y,w,h"` 声明人物脸、身体主体、服装标识和关键动作占据的百分比区域。
- 完全不叠文字时，容器写 `data-overlay="forbid"`；确需叠层时，写 `data-overlay="zones" data-copy-zone="x,y,w,h"`。门禁会计算两个矩形，重叠即失败。
- 所有正文文案必须声明 `data-copy-flow="horizontal|vertical"`。字多文案强制 `horizontal`，最多允许 1 个 `<br>`；只有符合上节阈值的极短口号才允许 `vertical`，门禁会拒绝长文案列式排版。
- 坐标均以当前容器左上角为原点，范围为 0–100；标记必须对应真实 CSS 构图，不能只为过检查填写。
- 仅历史冻结目录可通过同目录的 `.ribao-archive` 显式标记豁免人物 sidecar、人物像素探针与任意绘制层遮挡大字探针；当前仅 `0908`、`0910` 两个原样保留的拼贴实验版使用。新期、复制稿或改动后的归档稿不得沿用该标记，仍须 fail-closed 通过人物和文字双门禁；标题、素材唯一性、文案、封面、few-shot 和 PNG 等其他检查不豁免。
- raw 导出和 `ribao-check` 必须对 `[data-occlusion="copy"]` 大字执行权威光栅差分：隐藏除 copy 节点及其祖先链外的全部元素，生成只保留文字墨迹的干净基线，再与完整渲染比较。单通道差值超过 18 且文字墨迹内变化比例超过 0.5% 即失败，从而覆盖普通色块、截图、图片、贴纸、伪元素与阴影等任意绘制层。Playwright、截图或图像依赖异常都按失败处理，禁止“检测不到即通过”。
- raw 导出截图前必须检查合并 HTML 的全篇图片源身份；`ribao-check` 必须把正文与封面作为同一集合检查。图片、sidecar、源图或哈希不可读时 fail-closed；只有 `.ribao-archive` 明确标记的历史冻结稿豁免跨页源身份检查。素材不足时封面使用纯排版或未在正文出现的贴纸，不得回退复用正文图片。
- raw 正文必须在 1080px 实渲后执行真实内容密度光栅差分：隐藏文字、图片、贴纸和签名得到同版式背景基线，逐个 `section.scr` 统计有效像素。非 `shot-stack` 屏填充率不得低于 35%，所有屏内容总高不得超过 7400px；截图屏保留完整截图，仅豁免逐屏 35% 阈值、不豁免总高。人物主体图实渲宽不得低于 432px且高不得低于所属屏 55%，聊天截图宽不得低于 810px，补充证据图宽不得低于 480px。不得用背景换色、伪元素或空装饰色块刷指标；Playwright、截图或图像依赖异常按失败处理。`.ribao-archive` 历史冻结稿显式豁免这一探针。

结构示例：

```html
<figure data-layout="subject-safe" data-overlay="zones" data-copy-zone="4,72,92,24">
  <img data-subject="people" data-subject-zone="8,4,84,62" src="./assets/ride.webp" alt="双人骑行" />
  <figcaption data-copy-flow="horizontal">拿 KOM，爆金币。</figcaption>
</figure>
```

### 发布态回归

最终发布到公众号后，还要用发布链接回看一次；微信会把长图转成 JPEG/WebP，并在图片右下角追加公众号水印。发布态不是新的设计源，正文事实、模块顺序、图片唯一映射和人物像素仍以仓库 HTML/PNG 为准。

- 页面必须在页脚或非关键背景区声明 `data-platform-safe-zone="wechat-watermark-right-bottom"`，为微信右下角水印留出不含人脸、身体主体、Logo、路线数字和关键梗的区域。
- 不要为了水印人为拉长空白；安全区应与页脚/品牌条合并。发布后若只有编码饱和度、轻微压缩噪声差异，不反向调整源图配色。
- 发布链接只用于验收平台转码、水印和裁切；发现内容差异时先核对源 HTML、导出 PNG 与已上传图片是否同一版本。
- 已验证发布基准：`https://mp.weixin.qq.com/s/njZr19jAdslBWiT7uVETZA`（标题“日报回归 | 莫拉纪实报道”，正文为单张 1080px 宽长图）。
- 在 `xiaohuoche-ai` 项目中，`style/references/605/` 是唯一历史视觉 ground truth。`docs/ribao-html/0908/` 与 `0910/` 原样保留为拼贴实验版，不作为新稿视觉范本，也不得删除或改写其历史。新稿可复用其审阅和导出结构，但视觉判断必须回到 605。没有真实素材的栏目直接删除，不能用旧图或虚构内容补齐。

### 备注修改与成品下载

- 页面顶部保留 `data-export-ignore="review-tools"` 的审阅工具。默认使用“点选批注”把意见绑定到 `hero` 或 `section-XX` 稳定锚点，并记录相对位置、待处理/已解决状态和更新时间；整页说明只承载无法定位到具体区域的要求。
- 用户可在审阅队列中解决、重新打开或删除意见，并用 JSON 审阅包跨设备传递。收到审阅包后按 `pageId`、`schemaVersion` 和锚点校验，逐条处理待处理意见；处理后保留记录并标记已解决，不用截图替代结构化意见。
- 备注、定位点、按钮和状态提示都必须带 `data-export-ignore` 或位于该容器内；导出脚本会统一隐藏这些元素，任何审阅信息不得进入成品图。
- 页面通过 `body[data-download-file]` 指向当前整页 PNG，下载前先校验图片可读取；只下载已通过门禁的成品，不在浏览器内重新截图。复制范本到新日期时，必须同步更新文件名并先执行导出脚本，避免下载旧图。

## 历史推文视觉 DNA

细节见 [style-guide.md](references/style-guide.md)。关键不是“椰树广告模板”，而是 605 真稿的连续群刊结构：

- 一种天蓝底贯穿整页，短梗大标题、大图/群聊截图和极短正文连续出现。
- 大字逐行使用荧光绿、亮黄、白、粉紫、青、蓝紫，配粗黑描边和白硬阴影；不用厚黑线切屏。
- 图片、贴纸、编号允许 `±2deg` 轻微错位，形成手工拼贴和社交截图感。
- 不使用栏目编号、白色信息卡阵列或英文装饰；原生截图 UI 完整保留。
- 三层叠压为“截图底 → 大字层 → 粗白边加外层黑边人物”；装饰不得压文字、人脸主体或截图关键信息。
- 页面保持 1080px 最大宽度；移动端倾斜减半并改为单列。

### 人物抠图与大字背景

需要复刻历史案例中的人物剪贴时，只允许对原图做**非生成式前景分割、裁切与等比例放大**：保留原始像素中的真实人物，把透明 PNG 叠放在页面色块和大字前方。禁止使用生成式图片编辑，禁止换脸、补脸、美颜、磨皮、重绘五官、改变体型/服装/姿势或生成原图中不存在的身体部分。

- 优先使用传统/分割模型抠图工具输出透明 PNG；模型只生成遮罩，人物 RGB 像素必须来自原图。
- 抠图结果质量不足时直接使用原图裁切，不得用生成式修脸或补身体；宁可保留少量真实背景，也不能改变人物原貌。
- 群像需保留人数与前后站位；透明 PNG 先按 alpha 包围盒裁掉四周透明空边，再放进容器，以“裁空边、不裁人物”的方式最大化人物，而不是用 `cover` 硬切边缘人物。
- 人物头部和上半身应占主要画面，人物图尽量填满容器；单人优先“大头贴”构图，可裁次要下半身，但脸和服装 Logo/文字必须完整。
- 图片与文字优先叠层融合：文字放在图片安全区域、渐变底或人物后方，减少独立文字卡造成的纵向堆叠；一行能表达时不要拆成纵向多行。
- 人物和标题都要尽可能放大：先保证人物不缺失、脸不被裁、口号不出错，再压缩外边距、章节 padding 和纯背景面积。
- 背景色块和大字必须由 HTML/CSS 绘制并置于透明人物图后方，不得烘焙进人物图片。
- 用抠图替换原图时，不能让原图与衍生图在同一日报重复出现。
- 项目存在 `style/common-materials.yaml` 时，口号、品牌词和禁用替换以该文件为准；出图前后逐字核对，固定口号不得改写成近义句。
- HTML 负责黑边、硬阴影、轻旋转和图片说明。

## 公众号标题与封面背景

- 公众号标题用 `MMDD，小火车日报｜当期最强冲突梗`：前半段固定栏目识别，后半段只截取用户原话中最抓眼的一件事；不标题党、不新增事实，建议总长度不超过 30 个汉字。
- 每期必须单独交付 `title.txt`，内容为公众号标题全文；`title.txt`、正文 HTML `<title>`、封面 HTML `<title>` 和 few-shot 输出 `title` 必须完全一致。
- 正文首屏与公众号封面分开构图。封面使用 1080×460 横图，不得把竖版首屏直接硬裁成横图。
- 封面不是只放栏目名和一张人物图：先从全文选出 1 个主事件、1–2 个图片事件和 2–3 个补充关键词，组成“栏目标题 + 主梗 + 群像/主图 + 两张要点图 + 底部关键词”的内容精华；不能把所有章节原句塞上去。
- 封面人物优先放右侧或中央安全区，标题和当期梗放左侧；所有人物头脸完整，标题不压脸。
- 背景由 HTML/CSS 绘制高饱和色块、斜纹、`XZQ` 大字、粗描边和硬阴影；人物图仍只用原图像素，不把生成式背景烘焙进人物。
- 标题、封面 HTML 和封面 PNG 都要纳入当期范例目录；出图后单独验收缩略图状态下仍能读清栏目名和当期梗。

## 制作与导出流程

### 三层图片交付与字体规格

- 整页归档图始终保持 1080px 宽，禁止导出 2x 长图；超长 Retina 图片容易超过平台限制并被二次压缩。
- 正文分屏必须同时交付 `slices/1080/`（每屏 1080×1000 PNG）与 `slices/2160/`（同一 1080 CSS 画布、`deviceScaleFactor=2`，每屏 2160×2000 PNG）。公众号编辑优先使用 1080 分屏，手机端高清查看或抗平台缩放使用 2160 Retina 分屏。
- `result-manifest.json` 的 `outputs.slices` 指向 1080 主交付，`outputs.retinaSlices` 指向 2160 交付；两组数量、顺序必须一致，每一项都登记文件 SHA256。合成产物只允许 PNG，源 JPG 只能原字节复制，不能先转 JPEG 再进 ZIP。
- 两种倍率必须分别实跑人物零遮挡和文字零遮挡探针；不能因 HTML 相同就推定 Retina 安全。缺图、错尺寸、SHA 不符或探针依赖不可用均 fail-closed。
- 主大字正文不小于 88px、封面不小于 110px，字重 900；填充使用荧光黄 `#eaff00`、白 `#ffffff`、亮粉 `#ff5fb0` 或青 `#25f4ee`，黑描边 3–4px 并使用 `paint-order: stroke fill`，单层硬阴影 `8px 8px 0 #101820`。lead 不小于 40px、kicker 不小于 30px、caption 不小于 32px、date 不小于 28px。

双分屏导出：

```bash
python3 .trae/skills/xiaohuoche-ribao-html/scripts/export_html_png.py output/article.html \
  --output-dir output/slices/1080 --sections-only --section-height 1000 \
  --device-scale-factor 1
python3 .trae/skills/xiaohuoche-ribao-html/scripts/export_html_png.py output/article.html \
  --output-dir output/slices/2160 --sections-only --section-height 1000 \
  --device-scale-factor 2
```

### 一条命令发布与终审证据

新期稿件完成审核后，从仓库根目录运行：

```bash
scripts/ribao_release.sh --date MMDD
```

脚本严格按 `render(raw) → ribao-check → ribao-audit --strict` 执行，任一步失败立即停止并打印失败步骤；不要跳过失败项继续发图。成功时会打印整页长图、1080×460 封面绝对路径及 SHA256，可直接用于 `botmux send --images`。机器可读的终审证据同步写入 ignored 的 `build/audits/<date>-<shortsha>.json`，包含 Git HEAD/工作区状态、产物尺寸与哈希、人物/文字/图片唯一性/密度探针结果及逐图渲染尺寸。

首次使用前运行 `python3 pipeline.py setup`，并确认项目 `.venv`、Playwright Chromium、YuNet 和 rembg/u2net 可用。`ribao-audit` 与发布脚本均 fail-closed：缺依赖、缺 sidecar、哈希不一致、遮挡、重复图片、尺寸或密度不达标都会非零退出；`--strict` 遇到 dirty 工作区同样失败。试产产物只写 `build/`，不得修改带 `.ribao-archive` 的 0908/0910 历史归档。

1. 将素材压缩为章节清单，核对事实和原话。
2. 建立唯一图片映射。
3. 使用 `web-creation` skill 修改独立 HTML，最终文件放在 `output/`。
4. 使用 `deploy` skill 的 `html_vision` 检查标题遮挡、图片裁切、文字溢出与控制台错误。
5. 运行 HTML 校验脚本。
6. 运行 [export_html_png.py](scripts/export_html_png.py) 导出公众号图片：

```bash
python3 scripts/export_html_png.py output/index.html \
  --output-dir output/exports \
  --name xzq-ribao \
  --slice-height 2200 \
  --overlap 80
```

脚本固定按 1080 CSS px 渲染，等待字体和图片加载，强制关闭动画并隐藏固定交互控件；输出 `xzq-ribao-full.png` 与 `xzq-ribao-01.png` 等分屏图。`--slice-height 0` 可只输出整页图。

7. 单独导出公众号封面：封面 HTML 保持 1080×460；若截图工具使用最小视口高度，则用导出脚本的 `--crop-height 460 --slice-height 0` 从顶部精确裁切，不手工截图。
8. 检查 PNG 宽度、分屏数量、文件大小和可读性；优先上传分屏图，整页图用于存档。项目提供 `pipeline.py ribao-check` 时必须运行统一门禁，确认 `title.txt`、正文标题、封面标题、图片、few-shot、封面尺寸和全部 PNG 同时有效。
9. 提交代码后使用 `deploy` skill 部署 `output/`，再对线上地址执行一次 `html_vision`。

## 验收

- 原始素材主题数量不变，无新增事实、评价或剧情。
- 所有图片只出现一次且链接有效，页面可见缩写均为 `XZQ`。
- 页面具有模块堆叠、轻倾斜、粗描边、硬阴影与截图/贴纸感，但文字和主体不被遮挡。
- 桌面端、移动端与 1080px 导出图均无重叠、溢出、空白屏或透明内容。
- HTML 校验、PNG 导出与视觉检查均通过。
- 最终提供访问链接以及整页/分屏 PNG；公众号正文优先直接上传 PNG，不复制复杂 HTML。
